# 小说编译流程与完整性验收规范

版本：1；制定日期：2026-09-28。适用所有小说的首次编译、断点续编、定向重建及候选认证。

本规范约束执行、开发和结果报告，不宣称下述自动调度和门禁已经全部实现。实现尚不支持的检查或修复必须显式标为未验证／阻塞，由宿主按已有授权与工具能力处理。

架构依据：[ADR 0001](adr/0001-world-truth-history-and-possibility-space.md)、[ADR 0010](adr/0010-major-character-play-and-world-closure.md)。原文证据权威、proposal → validate → commit、角色知识隔离、不可变修订和分支历史语义保持有效。

## 1. 完成的定义

必须分别报告以下结果，禁止用批次数、产物数或归档成功推导整体完成：

| 结果 | 必需证据 | 不代表 |
| --- | --- | --- |
| 批次执行完成 | 当前源文件和有效计划下的必需批次完成，回执可验证，执行义务闭合 | 应有语义已经齐全 |
| 全局编译闭合 | 当前候选的必需来源、身份、证据、时间、语义依赖与记账要求通过，无未解决关键缺口 | 长期游玩体验已验证 |
| 候选已归档 | 可验证的不可变 bundle hash、来源和编译指纹 | 已激活、已认证或可以公开 Play |
| 可执行性认证通过 | 独立角色／场景／机制要求及适用运行探针通过，评估绑定当前候选 | 原文未描述的全部反事实世界都已确定 |
| 已激活／已发布 | 适用认证有效，按现有发布授权更新指针 | 旧分支被改写 |

“完整小说编译完成／可用”只用于约定的全书范围已闭合且适用认证通过的候选。仅要求候选归档的任务可以在归档后交付，但必须保留缺口和未认证状态。选定章节或场景的通过结果只能声明相应范围。

必需检查的 unknown、stale、未执行或不支持均不能算通过。非关键未知可保留，但需记录证据边界、影响和适用策略依据；不能为通过验收临时把关键项改为非关键。

## 2. 开始前固定检查对象

宿主在启动／恢复时记录并核对：

- source ID、不可变 SHA-256、书名和卷册范围；单卷结果不能称为全系列完成。
- 原文归档可读性、分段布局／结构版本、编译指纹及当前计划。
- 基底候选、当前 active revision、已有分支固定版本，以及本次目标：候选、定向修复或完整认证。
- 批次检查点、完成回执、持久失败义务、未结束写入、修复账本及编译锁状态。
- 适用验收策略／独立规格版本、必需维度、场景与角色分母、预算和停止条件。

检查先于模型调用。状态读取不应隐式迁移、修复、认证或激活。锁记录存在与进程存活分开表述；源文件或计划无法验证时，计划完成率为未知。

复用已有合法进度。中断的原始 finish 按原回执恢复；不能重置检查点、清空失败计数或轮换 ID 来取得新尝试机会。

## 3. 阶段交接契约

下表规定职责和验收边界，不要求使用一个巨大的模型会话。采用有界、来源限定的批次，保持阶段工具权限隔离。

| 阶段 | 必需交付 | 交接检查 |
| --- | --- | --- |
| 来源与结构 | 不可变原文、结构单元、分段及版本化计划 | 字节范围／哈希可信，来源单元有归属，布局变化可追踪 |
| 观察 | 实体提及、事件提及、引语、话语与来源锚点 | 锚点有效，单元有处理记录；独立复核重要遗漏；观察不直接成为世界事实 |
| 身份与语义 | 身份／事件决议、命题归属、事件、参与、时间／因果／场景 | 所负责提及有合法判定或持久缺口；提交依赖闭合；叙述、梦境、传闻与实际发生分离 |
| 可执行建模 | 动作／机制、状态与知识效果、规则／规范／过程、目标与入口 | 必需机制与效果有证据且可验证；无变化有依据；未映射语义显式阻塞 |
| 跨片段整合 | 共指、跨段因果／时间／知识、共享机制及入口依赖 | 邻接边界与非相邻引用均检查，变更影响及消费者失效可追踪 |
| 全局闭合 | 当前候选、全部缺口与独立要求 | 必需维度通过；延后项处理或依法保留为非关键未知；评估与修订一致 |
| 可执行验收与交付 | 冻结候选、独立角色名单／场景规格、运行探针 | 按第 7 节记录能力证据，再决定归档／认证／激活状态 |

阶段完成不能仅依赖“本次成功提交了哪些 proposal”。宿主必须根据上游清单和独立要求核对“本阶段应处理什么”，防止模型漏提对象从分母中消失。

观察清单本身也可能漏项，遍历清单不等于全书召回率。应独立复核重要角色、关键事件和机制，保留抽样范围、未复核范围及新发现的要求。

允许后续上下文解决前期歧义：局部检查点可以证明本轮审阅完成，但遗留事项必须登记并转交，不得计为语义闭合。跨阶段依赖由宿主安排后续合法 scope；不得要求观察阶段越权写世界真相。

## 4. 来源记账与覆盖率

每个文本单元应有适用的处理判定，或明确未解决／延后记录。使用现有 schema 支持的分类，不为指标引入绕过类别。

- 已记账率与已表示率分别展示；记账 100% 不等于语义覆盖 100%。
- 延后项说明缺什么、依赖谁、由哪个后续 scope 处理；关键延后项阻塞完整认证。
- 背景／重复／非指称判定不能隐藏独立行动、知识获得、条件变化或未解析对象。
- 对高比例排除类别进行风险抽样，记录样本选择、原文依据和结论。比例异常是复核信号，不直接证明错误；不设置适用于所有小说的固定产物密度。
- 分母缺失时报告未知。独立角色名单和能力要求不得由现有产物、已就绪角色或成功案例反推。
- 原文支持“没有变化”与当前本体“不能表达变化”必须区分；后者记为未映射，不得伪装空 delta。

## 5. 缺口账本与修复授权

必须区分工具／proposal 执行义务与语义／能力缺口。前者为零不能证明后者为零。复用现有 requirement、reconciliation、upstream repair 与 receipt 机制，不另造互不对账的权威数据源。

每项缺口至少可追溯以下信息；存储尚不支持时在报告中补充，不声称系统已自动持久化：

| 信息 | 要求 |
| --- | --- |
| 身份 | 稳定缺口 ID、source ID、种类及受影响对象 ID |
| 发现依据 | 来源范围、审计／独立规格、检查条件与诊断；区分已证明错误和待复核风险 |
| 版本 | source hash、候选／工件修订、检查器及规格版本 |
| 严重性 | 是否阻塞当前交付范围、原因及策略依据 |
| 依赖与归属 | 上游缺口／工件、负责阶段、后续合法修复范围 |
| 生命周期 | 待处理、依赖阻塞、待宿主审查、已验证解决或已失效，映射到现有账本状态 |
| 授权与尝试 | 诊断是否仅供建议、已授权 scope、预算／剩余纠正机会及停止原因 |
| 解决证据 | 接受修订、重验结果、依赖闭合与完成时间 |

诊断计划不自动授予写权限。宿主在既有用户授权范围内创建来源限定、版本绑定的修复 scope；已有有效授权应复用。超范围、能力未映射或 host-review stop 按实际协议处理，不重复询问已经授权的常规步骤。

缺口解决以重验通过为准，不以模型声明、工具调用成功或新产物数量为准。分页／预算截断必须留下全部未返回任务的可发现入口或 ID，不能丢失队尾。

## 6. 编译内部的有界修复循环

1. 对当前来源／候选执行确定性审计，合并独立规格与角色／场景评估；保存各自版本与范围。
2. 将诊断分为执行恢复、缺失解析、证据缺口、记账延后、跨段依赖、可执行语义、未知／未映射能力。不能用一个 `blockingIssues.length` 代替全部维度。
3. 宿主按依赖排序生成最小可行修复范围，优先处理会阻塞多个下游对象的缺口。
4. 在合法工具权限内读取原文与当前完整工件，模型提交窄类型提案，宿主验证并提交，保留原 ID／修订和失败历史。
5. 重验修改对象及传递消费者。旧评估失效不能沿用；影响范围无法证明时扩大审计范围，不能假定无影响。
6. 更新账本并记录前后差异，再检查全局必需维度。目标满足才结束，否则继续仍被授权且有进展的有界任务。

修复范围可能扩展到非相邻章节。只有源文件／布局不兼容、系统性提取缺陷或有依据的影响分析支持时，才要求全量重编；不能因一个缺口清空全书进度。

“有进展”体现为具体缺口得到验证解决、必要依赖建立或新的可信诊断，不能以 token 消耗、再次运行或产物增加代替。先满足高风险依赖，不能只追求缺口总数下降。

以下情况停止相应执行并保存可恢复状态：

- 原文不足、语义冲突未能裁定、现有本体无法表达必需能力；
- 写入结果不确定、未完成回执、版本／作用域冲突；
- 达到既有纠正上限、预算／熔断边界，或没有可验证进展；
- 明确的宿主审查要求尚未处理。

停止不等于丢弃候选，也不等于全书失败。报告已完成部分、阻塞对象、证据、所需宿主动作及恢复条件。不得降低门槛、删除有效提案、改名重试或补造事实。

工具失败遵守 [工具恢复协议](agent-tool-recovery.md) 和 [有界纠正规程](compiler-self-correction.md)。ID/ref 错误先用同作用域发现工具，复制其精确返回字段，最多一次实质纠正重试；host-state、scope、single-use 和 circuit-breaker 停止条件优先。全局循环不会重置单项失败的重试额度。

## 7. 最终验收与证据边界

必需检查至少覆盖下列维度；适用性由版本化策略／独立规格确定，不能为当前候选临时豁免：

- 来源与记账：不可变证据完整，关键未处理／延后项闭合。
- 身份与语义：必需提及决议完整，引语、归因、知识获取、时间和场景关系有效。
- 证据支持：引用合法、精确字段绑定齐全，并完成适用的语义支持复核。锚点有效不等于语义蕴含成立。
- 世界依赖：因果／条件关系有来源依据，关键剧情可推进；真实独立事件允许独立，禁止把章节顺序伪装成因果。
- 可执行效果：必需动作、机制、规则及状态变化可验证；被动参与不授予施事权；不通过空操作或无意义状态字段凑阈值。
- 角色入口：独立名单中的必需角色有证据支持的时间切面、状态、知识、动机及适用机制，不导入未来结果。
- 运行能力：在隔离的冻结候选上执行适用入口／行动／知识隔离／重放探针；用独立规格检查关键场景，并验证改变关键前提后不会强制重演原剧情。

运行探针、真实模型多回合体验和人工评审分别记录。代码单元测试通过不能替代小说数据验收；有限探针通过不能声称长期体验已证明。未执行检查必须显示未验证。

认证绑定候选、来源、依赖、规格及检查器版本。修订后失效的认证需要重验。候选归档可先于认证，但不能提前激活或发布为通过认证的世界；旧分支固定历史不得被重建覆盖。

百分比阈值只是对应策略的一项门槛，不是完整性定义。空规则集、空空间图等不能因“无验证错误”自动证明能力齐备；应按原文和独立场景需求判断是否必需，也不能为了数量凭空添加。

## 8. 统一进度与交付报告模板

CLI、Web、脚本及人工报告保持同一语义，不要求所有入口一次执行全部阶段。底层命令退出成功只证明它声明的任务完成。

```text
检查时间／工作区：
小说／卷册／source ID／SHA-256：
候选 hash／父版本／active hash：
编译指纹／验收策略与独立规格版本：
本次目标与范围：

批次执行：已完成 X / 当前有效计划 Y（计划不可验证则为未知）
执行义务与回执：未闭合数量／需恢复数量
来源记账：已记账／已表示／关键延后，分别列分母
全局闭合：通过／未通过／未验证／已失效，逐维度说明
可执行认证：角色与场景分母、探针结果、未验证范围
候选归档：有无及 hash；激活／发布：有无
整体状态：处理中／待修复／待宿主审查／候选已归档未认证／已认证

当前缺口：种类、数量、关键 ID、影响、负责范围及证据
本轮进展：修复前后差异、接受修订、重验结果
停止或下一步：精确任务、依赖、授权状态及恢复条件
验证局限：未执行检查、抽样范围、未知分母、过期结果
```

禁止用固定的“批次占总进度 90%”掩盖动态修复工作量。保留批次百分比时，总状态独立显示。历史失败与当前未解决失败分开；状态快照与新执行的审计分开；费用／token 仅按记录说明口径，不推导质量或剩余工期。

## 9. 实现与回归要求

实际命令见 [核心编译与重建指南](novel-world-core-and-rebuild.zh-CN.md)。独立要求及诊断授权边界见 [semantic-requirements](semantic-requirements.md)。本规范不新增 CLI 参数、工具 schema 或持久化格式。

后续实现优先复用 `compiler/status`、`audit`、阶段 finish、既有 requirement／repair ledger、候选闭包及认证路径。统一发现和转交缺口的调度、逐阶段分母门禁及各入口状态展示，需以实际代码与回归证据确认，不能因本规范落地而标为已实现。

修改这些路径时至少覆盖以下回归场景：

| 输入情况 | 必须观察到的结果 |
| --- | --- |
| 全部批次完成但存在缺失提及解析 | 批次可为 100%，整体不得就绪，缺口可定位和转交 |
| 全部单元已记账但存在关键延后 | 记账覆盖率为 100%，全局闭合仍阻塞 |
| 没有无效引用但精确绑定不足 | 不声明证据完整就绪 |
| 局部事件合法但关键推进关系缺失 | 全局诊断保留，不按章节强接因果 |
| 上游身份／机制修订影响其他章节 | 重验消费者，过期认证不复用 |
| 归档未经认证的候选 | 保留候选，active 与既有分支不变，状态明确未认证 |
| 修复中断、额度耗尽或重复无进展 | 保存账本和回执，按协议停止，不重置 ID／计数 |
| 缺少本体映射或独立分母 | 显示未映射／未知，不伪造空效果或缩小分母 |
| 所有适用检查通过 | 仅对绑定版本和声明范围给出可追溯的通过结果 |

## 10. 本次经验的可复用结论

2026-09-28 的本地《龙族Ⅰ》检查中，72/72 批次完成、执行义务为零，但仍有缺失身份／事件解析、关键延后文本、证据绑定缺口和事件推进不足；候选已归档，未记录完整认证。这是当时数据的观察，不是所有小说的默认状态，也不证明历史执行路径的全部原因。

长期要求是：让“应有内容”进入宿主维护的分母，让未解决问题都有后续归属，让修复留在有界且可恢复的编译流程内，让最终完成声明由当前版本的独立验收证据决定。
