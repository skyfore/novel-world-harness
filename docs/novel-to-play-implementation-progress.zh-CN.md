## W1/W2：三个接口反例修复

- 人物提议统一规范化动作；玩家 action 在匿名句柄边界编码／解码，普通玩家不再跳过 any-action 约束。

- 分支知识凭 projector 生成且校验完整内容的进程内 provenance 准入；模型布尔值、复制条目、别来源条目不能冒充已验证知识。角色获取与祖先范围由共享投影决定。
- 首轮相关回归：7 文件／50 项通过。补充了合法足时、过快、错误方式和缺方式的直接引擎对照。
- 引擎契约切换到 0.3.0，旧引擎历史按已有版本校验拒绝混读；世界状态和 prepared 格式在对应后续工作包切换。并未声称所有机制授权、角色视图和五类效果已全部完成。

## W2：统一决策视图

- `actor-decision-view.ts` 派生当前角色的目标、评估、关系、义务、规范及过程，接入玩家、直接 NPC 与自主角色的共同上下文。
- 角色仅自动读取自身的关系态度；被指向的人不会因此获得对方的私有态度。活动目标包含已提交的 branch goals，修复 NPC 仅读 canonical goals 的问题。
- 新引用在 Pi 模型边界使用 semantic 临时句柄，保留人物与 head 隔离。
- 验证：`pnpm run check`；玩家、NPC、Pi 边界、自主角色与新增回归共 6 文件／57 项通过。

## W3：五通道运行与原子预检

- 玩家、NPC、Pi NPC 解码、编译动作及自主角色统一保留 semantic/process/norm 三个附加通道；知识与状态继续沿用现有契约。
- `actor-outcome.ts` 统一字段复制、类型化引用映射、角色可见引用和最终写入归属。新目标和态度归人物自身；债务由债务人接受，履约／免除由债权人确认。
- 角色视图包含有来源时序依据的动作／过程／规范能力模板；模型使用临时句柄和局部引用，文本字段不做递归 ID 替换。
- `previewProposal` 与 commit 共用同一完整验证流程，预检不写对象或移动 head。新命题与同回合 learn 可一起验证；任一通道错误均不能留下半次提交。
- 实际 PlayerTurnService 五通道场景、模型边界来回转换、跨角色非法写入及原子失败回归通过。验证：`pnpm run check`；6 文件／63 项通过。

## W4：入口切面与名单内核

- `entry-cut.ts` 使用故事时间、明确先后关系和事件共指推导 pre-event cut；当前／未来效果不进入初态，重复叙述只应用一次，关键顺序未知或冲突明确阻断。
- 历史入口早于开篇时必须提供完整 checkpoint，不能把晚年开篇状态带到年轻时期。
- `projectionSeed` 在 Genesis 原子校验并保存语义、过程、规范与有效规则；显式 cut 不再凭初始状态相似性推断未来事件已发生。
- `role-roster.ts` 从人物实体和未解析人物提及建立独立于可玩列表的分母；要求两个不同于抽取的复核运行，完整覆盖来源单元，保守合并 major 判定。
- 验证：`pnpm run check`；入口、名单、真实角色创建与五通道再入场共 5 文件／20 项通过。名单复核工具、发布接线和逐人物认证继续实施。

## W4：复核工具与生产内核探针

- 专用 role-roster 编译会话分页读取候选与原文，宿主记录完整原文页面覆盖；判断只能引用实际来源单元。前一次复核意见不进入下一次模型视图。
- 复核为单次 typed proposal，finish barrier 成功后写入；普通编译阶段不暴露这些工具，错误保留 Pi 的真实失败语义和明确恢复步骤。
- `playability.ts` 在隔离命名空间复用 WorldContextStore、WorldEngine、角色视图、fork 和 fsck，逐 major 记录 Genesis、决策、意图、等待、resume、fork 结果。缺少完整种子／生命状态／位置／计划的人物保持 blocked。
- 验证：类型检查通过；编译工具与复核 finish 共 55 项通过；实际引擎逐人物探针 1 项通过，验证一个可玩人物和一个缺入口 major 同时保留在分母中。
- 发布流程与 CLI/Web 的接线、严格证书以及长链路模型评测尚未完成；上述探针不能单独证明全文语义正确或长期角色保真。

## 全套回归的兼容修正

- 首次全套运行：153 文件，874 项通过、9 项失败。8 项来自旧 fixture 直接移动且没有路线／方式／耗时，1 项来自没有固定来源的多来源 legacy branch。
- 公共 CLI/Web/TUI 回归基底现提供原文证据、明确路线、步行方式和足够耗时；多来源基底显式固定来源。没有放宽空间或来源门。
- 修正后对应 5 文件的 84 项用例已逐项恢复通过；后续集成仍需再次运行全套 gate。

## W7：未知与后台公平性；格式集成

- 开放世界谓词使用 true／false／unknown，not(unknown) 不再变为 true；显式声明 closed-world 的字段可以使用缺失即否定语义，规则激活与逻辑时钟继续使用完整投影。
- 后台候选失败后在相同 head 上排除并尝试下一候选；成功提交才消耗推进预算，输入变更后才重新评估，单次调度仍有候选尝试上限。
- 4 文件／21 项相关测试通过，包括队头失败后合法候选成功，以及未知事实／时间取反仍不能授权。
- 按集成契约切换 world schema V3、world storage v3、prepared V4、cache format V3、prompt 27；引擎保持 0.3.0。来源字节不删除，旧世界不自动迁移。

## W1：机制与发起者权限

- actor/player 的真实物理、财产或身份变化必须绑定经过验证的动作机制；ad-hoc 标签及精确 footprint 均不构成授权。自身意图与已验证路线移动保留各自的确定性通路。时间自然造成的年龄变化独立于角色显式写入，避免等待被错误拒绝。
- 动作 schema 明确必填 initiatorRoleId，实际调用必须将该角色绑定到 actorId，防止借用另一角色的所有权或能力。
- 模型参数按 schema 的值类型映射实体引用，不再将字面字符串当作实体 ID 改写。
- 更新原有合法用例为有机制的赠与／关门、有来源路线及足够耗时的移动；49 项玩家、动作和反例测试通过，另有 NPC／多角色针对性回归通过。

## W5：候选闭合检查与统一发布门

- `closure.ts` 从明确的类型化引用建立依赖图，记录修订哈希与悬空引用，按反向依赖固定点计算失效集合，身份环不会导致无限遍历。
- 候选检查冻结完整 source／canonical／compiler snapshot／roster；逐人物探针绑定 subject、名单与入口切面。发布、激活、恢复、新建 Play 复用严格证书检查；失败不切换 active，回滚基底仅归档。
- 证书重查原文 partition、accounting、准确的主要人物分母、不同探针种类、角色身份与切面；缺独立语义 gold 或真实 Pi 长程评测时为 blocked，单测不生成生产认证。
- 两次专用名单复核接入 CLI 准备流程；可报告实体和提及清单均未包含的人物，该人物保持未解析并阻断。
- 评测报告契约保留全部语义层、精确分母、Wilson 95% 区间函数、冻结任务与关键检查清单、每人三次运行和至少 50 个实际物质／社会效果提交要求。重复、无效果、任务删除、确定性替身不计为通过。报告保留不可变版本，重新评测原子更新索引。
- 验证：`pnpm run check`；6 文件／29 项通过。旧手写世界的组件用例在测试边界隔离新认证流程；真实发布拒绝路径有独立测试，不将组件 mock 计为全文质量证据。
- 依赖索引的定向修复调度、Web 完整接线、独立 gold／实时评测执行器及最终全量验收继续实施。

## W6：统一角色入口与准备诊断

- `play-roles.ts` 为 CLI、Web 和准备诊断提供相同的角色投影，未解析和无入口人物不消失；ready 必须具有身份、入口切面和无阻塞的认证。
- 新建 Play 同时绑定 prepared revision 与 entryCutHash；选择后和 Genesis 前均检查，旧切面返回明确刷新错误。Web 沿用持久化请求幂等机制，重复请求保持同一实例／会话。
- 原著来源的新建入口不再回退到未认证初态或任意 seed；无来源的内核实验仍可以直接验证 Genesis。默认人物来自已认证名单。
- CLI `prepared-cache inspect-closure` 可检查候选及缺失证据而不发布；Web 工作台显示全部人物状态、入口探针分母和未运行／失败的独立评测，未认证时禁用创建。CLI、Web 和 TUI 准备均执行独立名单复核。
- 验证：类型检查通过；6 文件／84 项通过，包含入口切面变化拒绝、Web 重复请求幂等、未解析 major 保留及原文来源 seed 绕过拒绝。此验证不等于真实整本模型认证。

## 动作接线的最终差分修正

- 玩家作用域允许当前已知机制明确声明的非自有目标效果，仅限精确绑定效果；不因此开放对方私有状态读取。动作模板的 stateEffects 进入共享决策视图，模型有可执行的字段／角色依据。
- 动作效果使用多重集合计数，重复同一数值操作不能将一次授权放大。编译角色与混合自主策略均保留明确动作耗时，避免规则验证通过而提交丢失时长。
- 补充非法探读对方财富被拒绝、合法转账只修改绑定账户、重复效果不放行等实引擎用例；旧规则／旅行 fixture 改为明确路线或已声明机制。
- 验证：类型检查通过；6 文件／65 项通过，新增精确目标效果测试所属 3 文件／46 项通过。

## W8：冻结 gold 与真实 Pi 评测执行器

- 新增 `prepared-cache freeze-evaluation <plan-json>` 与 `prepared-cache evaluate <plan-hash>`。先固定独立 gold、全部 major 的入口切面、任务、知识隔离检查和非法动作反例，再允许运行；冻结内容改变即拒绝读取。
- 语义评分直接读取同一不可变 candidate，避免运行中混读当前编译目录。每个 major 建立三个隔离世界，使用生产 Pi 适配与 `performPlayTurn`，保留真实调用 trace、提交链、反例拒绝与全量回放检查。
- 计数排除纯台词、计划、动量、时钟、自然年龄变化和重复状态；达到回合上限或停滞记失败，只有冻结的终止谓词可以提前结束。没有实际完成的 Pi 调用不标记为 live。
- 每次运行均写不可变评测记录；未完成的运行与未标注语义层保持阻断，重新运行不会覆写历史。输出各层 precision／recall 和 Wilson 95% 区间。
- 验证：类型检查、3 文件／9 项测试与生产构建通过。测试证明不完整入口的三次评测均失败且不产生认证或 active revision；没有使用假模型结果生成生产证书。当前环境尚未运行真实整本 Pi 评测。

## W5：跨章节依赖修复与安全恢复

- 闭合索引补齐 discourse、事件决议、真实 artifact kind 与旧版证据到来源叶单元的依赖。章节重解析先按受影响消费者与其来源依据计算固定点，自动扩展必要章节，不因 work 容器或名单全文复核把任意修改扩展为整书。
- 定向失效使用类型化节点键；CLI 检查输出稳定 issueId／输入哈希、根因优先的修复阶段、缺失引用与受影响节点。重复输入不会产生不同的修复计划。
- 新增仅恢复编译数据的 checkpoint 操作。未认证归档可用于失败恢复，但不能改变 active 或绕过新建 Play 门；旧 pipeline 恢复不会重盖当前语义版本。
- source accounting 进一步校验 represented 所引用的注释／证据确实存在并覆盖该来源单元，避免只填 ID 即计入完全性。
- 验证：闭合、真实发布门、重解析及历史修复共 4 文件／17 项通过，包含跨章节消费者失效与无关章节保留、未认证归档恢复后仍未发布。

## 角色能力与履约确认的补充修正

- 动作能力中的实体引用集合和参数候选值也接受角色可见性过滤；自定义状态字段保留真实 valueType，在模型边界正确映射临时句柄。
- 发起过程不能把未同意的其他人物登记为共同执行者；人物自行提交的规范履约／补救声明需要受益方确认，确定性规范机制仍可根据真实动作识别履行。
- 核心动作回归 2 文件／49 项通过，包括隐藏能力参数与自定义实体集合、无回执自宣履约的拒绝。

## 最新实施重点

按用户最新要求，优先完善 Pi 小说编译的结构、语义／机制接线与可恢复 rebuild。Web 浏览器回归暂停；不将缺浏览器环境的未运行项记为通过。

## Pi 核心：语义事件与执行机制接线

- 新增独立 `EventExecution`：在 executable 阶段将先前 accepted 的 canonical event 绑定到 action schema、发起人物和精确参数。核对语义 agent 参与、来源、发起者角色、重复／冲突绑定和完整效果多重集合；原始事件不被重写。
- `propose_event_execution` 接入 Pi 阶段工具、同作用域检索和失败恢复；对应 canonical store、proposal/converge、审计、reparse、prepared 与 frozen context 均支持该类型。
- 场景执行契约核对主要人物事件覆盖、角色入口、退出谓词、知识获取路径和传递依赖。普通旅行复用实际 pre-event 状态、活动路线、方式与最短耗时；一次旅行不强迫泛化成新行动定律。
- `SupportAssessment` 区分原文定位和独立语义支持。没有独立复核为 underdetermined；不允许整项机制没有 evidence binding，也不允许只复核一个效果就认证其他前提、例外或权限。独立复核随冻结的评测计划和报告保存。
- 依赖图增加字段 JSON Pointer 与用途、accepted discourse、事件执行绑定、类型化参数／实体集合，以及初态和入口的知识、语义、过程和规范依赖。入口局部命题／claim 不误报为缺失 canonical；失效沿新旧图的消费者固定点传播。

## 核心 rebuild：归档与发布分离

- 新增 `nwh rebuild`：可以从原文及现有批次进度继续完成首次候选，或从明确历史 revision 复用工件重建；`--chapters` 自动纳入跨章节消费者。
- journal 记录 immutable parent、原 active、模式、章节、精确批次与 initializing／compiling／finalizing。先持久化初始化意图再使批次失效；中断保留已接受工件和已完成批次。
- 恢复核对版本、来源布局、章节、proposal namespace 和 active；冲突不覆盖，重复执行相同 rebuild 即恢复。历史编译快照的恢复不会激活未认证世界。
- rebuild 输出不可变 candidate hash 和 parent lineage；缺少全书 gold／真实 Pi 长程证据不丢弃编译产物，也不解除公开 Play 的严格发布门。
- 晚出场入口保留此前显式耗时；开篇已有非物理状态却缺少晚出场完整种子时，返回 `ENTRY_PROJECTION_SEED_REQUIRED`，不静默遗失承诺或过程。
