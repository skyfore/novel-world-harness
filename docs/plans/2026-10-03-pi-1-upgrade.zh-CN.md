## 范围与收益

升级继续使用 `AgentSessionRuntime`、`AgentSession`、`SessionManager` 和 `ModelRuntime`。NWH 仍负责 domain prompts、工具授权、提案验证、世界提交和角色知识投影。

| 上游变化 | NWH 采用方式与收益边界 |
| --- | --- |
| TUI 内存与渲染优化 | 保留原生 transcript 与任务面板，验证长记录滚动、搜索、流式响应和内存。上游单条长 assistant 消息约保留原来 1/5 堆内存的结果，不能直接当作整个 NWH 的性能指标。[1.0.0](https://github.com/earendil-works/pi/releases/tag/v1.0.0) |
| 压缩、取消与重试修复 | 验证大工具结果触发压缩、取消等待及压缩期间的恢复行为，减少长编译任务的运行故障。[0.84.4](https://github.com/earendil-works/pi/releases/tag/v0.84.4)、[0.86.0](https://github.com/earendil-works/pi/releases/tag/v0.86.0) |
| SessionManager 上下文权威和追加式 context edits | 适配 provider 历史与生命周期；保留原始记录和模型可见投影的区分。第一期不主动将 NWH 的全部投影改成持久化 context edits。[0.87.0](https://github.com/earendil-works/pi/releases/tag/v0.87.0) |
| 新模型和 provider 修复 | 验证现有 profile、自定义 endpoint、模型选择和认证兼容性；不自动改变用户选定的 provider/model。[0.99.0](https://github.com/earendil-works/pi/releases/tag/v0.99.0)、[0.99.1](https://github.com/earendil-works/pi/releases/tag/v0.99.1) |

本次不启用 codemode、MCP、虚拟模型路由、分类器或图像生成。NWH 已默认 fullscreen；上游 codemode 默认配置的约 40% prompt token 降幅也不适用于当前 NWH 工具集合，不列为本次验收收益。

不迁入 Pi Durable，不增加数据库，不替换编译账本、工作区存储或世界事件模型。Pi 1.0 从 agent-core 移出了实验性 durable harness；当前 NWH 没有使用该 API，常规 SDK 升级不要求切换 runtime。[agent-core 变更记录](https://github.com/earendil-works/pi/blob/v1.0.0/packages/agent/CHANGELOG.md)

## 实施设计

### 依赖和补丁

同时更新三个直接依赖，生成 `patches/@earendil-works__pi-coding-agent@1.0.0.patch`，更新 `patchedDependencies` 与 lockfile。清理不再适用的 `0.84.2` release-age 例外；如安装策略需要例外，只为实际锁定的目标包版本添加精确例外，不全局关闭发布年龄检查。此次保留现有 Node、pnpm 和非 Pi 依赖的版本范围，独立审查必要的传递依赖变化。

基于官方新包逐项重做 patch，不直接复制旧 dist 文件覆盖新实现。patch 的保留范围是：

1. 扩展拥有的 `TransientAssistantStream` 及 `openTransientAssistantStream`：子会话输出进入原生 transcript；验证后原位提交一次，拒绝或取消时移除；不能进入父模型上下文。
2. `ThinkingDisplayMode` 与组件状态：支持 active thinking、完成折叠、Ctrl+T 展开，并保留旧 `hideThinkingBlock` 设置的兼容读取与迁移。
3. 首条已提交自定义 assistant 场景的持久化与恢复。新版对首条 user 消息的修复不自动覆盖 NWH 的该入口。
4. `resumeCommandFormatter`：退出提示保留准确的 NWH root、session 和 compiler 入口。

补丁说明逐项记录为何仍需保留、对应回归测试及可删除条件。类型声明和运行时实现同步修改。不得为了脱离 patch，把子会话重新注入父会话、重复挂载已确认场景或放弃持久化。对不需要修改上游的辅助逻辑，优先放回 NWH adapter。

### 工具参数与宿主执行

在 Pi 边界将已验证输入收窄为 `JsonObject`/`JsonValue`，不能只用 `as any` 或 `JSON.parse(JSON.stringify(...))` 掩盖不合法值。外部输入仍须通过现有 schema；无法表示的值明确失败，不静默删字段。

`upstream-repair-staging.ts` 当前通过空对象断言成 `ExtensionContext` 来直接调用 proposal tool。迁移时为宿主 staging 和 Pi tool adapter 提取共用的、显式传参的 proposal 执行入口，保留原有 `prepareArguments`、recovery、证据验证、账本授权和写入收据顺序。禁止把空对象换成更宽的 `ExtensionToolContext` 断言，或为宿主 staging 临时开放全套工具执行能力。

工具声明、活动工具集合及最终 provider payload 都要验证作用域。新增 `ctx.executeTool()` 和 nested-call 能力不能绕过 NWH 的原 batch、原 source、纠正次数与串行提案约束。继续保留 `isError=true` 和有界 SOP；ID/ref miss 必须指向同作用域发现工具及精确返回字段，host/scope/single-use/circuit-breaker 停止条件继续优先。[工具恢复规范](../agent-tool-recovery.md)

### 会话上下文与隐私

Pi 0.87 起由 `SessionManager` 决定 provider 历史；`context` 事件只处理非 system 消息，之后 Pi 恢复 system/tool 状态，`context_with_system` 才处理完整 transcript。NWH 不依赖修改 `agent.state.messages` 控制后续历史，也不把 context edits 当作世界事件或证据。

实施时维护三条明确边界：

- `context` 保留 NWH 的普通会话、当前 compiler span、玩家显示消息投影。新增 session entry 类型必须显式分类；不能因为不认识就进入摘要或角色证据。
- `session_before_compact` 和 `session_before_tree` 继续使用相同的角色投影与可信摘要 marker。压缩后的恢复、fork、resume、tree navigation 和重试均不能重新带入其他角色或未来 canon。
- `before_agent_start` 继续生成、脱敏 NWH prompt；新增完整 transcript 的最终检查，覆盖持久化 system 消息和工具声明。常规、compiler、actor、narrator 及关闭主 NWH extension 的会话都适用。核验失败必须在 provider transport 前真正停止，不能只抛给会吞掉扩展异常的 hook runner。

Trace 在隐私处理之后观察内容；区分投影后的逻辑消息、完整 system/tool 上下文和最终 provider payload。未脱敏的宿主路径和凭据不得进入日志。现有两个依赖私有 `emitBeforeAgentStart` 签名的测试，改用真实 session 加模拟 provider 捕获请求，验证最终出站行为；不降低隐私断言。

### 压缩与请求预算

`StreamFunction` 输入已从 `Context` 改为 `TranscriptContext`，system 与 tools 位于消息中。调整观测和预算适配，避免遗漏 system/tool 字节或重复计数；字节统计不能标为真实 token 用量。

普通调用、自动重试、手动压缩、自动压缩和 branch summary 必须经过同一个 NWH 请求预算边界。分别记录逻辑调用和实际 payload 尝试，延续当前累计预算语义；压缩失败、取消或重建 session 不能重新授予额度。补齐 main 当前 summarization 调用的 payload admission 和 usage 归集检查，不能因 Pi 内部绕开 `agent.onPayload` 漏记。`ccd1b11` 已有相关实现，后续合并时比较并复用，避免保留两套计费/观测包装。

**第一期明确禁止 NWH 自动缓存保温。** Pi 1.0 的 `getCacheWarmingMode()` 默认 `streaming`，读取 `globalSettings`；`applyOverrides({cacheWarming: "off"})` 只改合并设置，不能单独保证关闭。缓存保温通过 `ModelRuntime.streamSimple` 发送请求，需防止绕过现有 agent 预算。

在始终加载的 NWH 策略扩展中处理 `cache_warming_decision` 并返回 `{ action: "stop" }`，不保存全局设置。测试要将全局 warming 分别设为 streaming/idle、推进模拟时钟，并断言常规与隔离会话均未发出保温请求；初始化或 reload 丢失该策略时须停止模型调用。不要通过 `setCacheWarmingMode()` 改写用户共享的 Pi 偏好。未来启用保温须另行定义预算、trace 与收益实测，不作为此次升级的成本承诺。[设置源码](https://raw.githubusercontent.com/earendil-works/pi/v1.0.0/packages/coding-agent/src/core/settings-manager.ts)、[保温请求源码](https://raw.githubusercontent.com/earendil-works/pi/v1.0.0/packages/coding-agent/src/core/cache-warmer.ts)

### Provider 和前端

保留显式 profile、命令行 model override、保存的模型选择及 provider 默认值之间的当前优先级。对已从上游目录撤下的模型，验证既有错误/回退策略并给出准确诊断；不能用新版默认模型掩盖恢复失败。模型选择单元测试使用可控目录，目录本身另做 smoke 检查。

自定义 endpoint 需验证 provider adapter、thinking、stream events 和工具结果重放。CLI 的 `/login`、`/model` 与 Web 模型设置继续复用 Pi 的凭据边界，浏览器只接收状态和脱敏信息。无需为了新增模型自动迁移用户的登录方式。

NWH 继续关闭 built-in 模型工具、外部扩展、skills、prompt templates、context files 和 ambient themes。核对 1.0 的 `noExtensions`/`noTools` 对 built-in extensions、全局配置和 reload 的实际效果，不能只比较配置布尔值。保持 sequential proposal/capture 工具和用户手动 `!command` 的权限区分。

真实模型验收使用同一固定 source hash 的小范围样本、独立工作区和固定 provider/model/thinking，分别执行一个 compiler scope、一个玩家行动与叙述回合，以及可触发压缩/取消的长工具输出用例。自动化模拟至少覆盖两种现有 provider 协议；真实调用只使用实施时已配置并获授权的 provider，分别记录未覆盖协议和认证路径。

报告模型调用次数、实际 token/费用（provider 有返回时）、错误/重试/压缩结果及证据和提案回执。不用生成文本完全相等作跨运行标准。按[小说编译规范](../novel-compilation-protocol.zh-CN.md)分别报告批次执行、语义闭合、候选归档、可执行认证和激活状态；小样本通过不表示全书完成。

性能验证使用固定 transcript、终端尺寸和模拟 stream，旧/新版本各运行相同次数，记录 Node 堆/RSS、请求装配、渲染/搜索耗时及冷暖启动差异。判定标准是同条件下无可重复的明显退化；观察到退化必须定位、修复或在交付记录中解释。未实测前不承诺固定内存、延迟或成本降幅。

## 数据兼容与回滚

Pi 的两个版本都声明 session format version 3，但新版允许新的 entry 与 system-message 语义，这不能证明降级后能正确解释新增历史。升级前在停止相关写入后保存 workspace session、last-opened 指针、NWH 设置和必要 Pi 设置的独立备份；凭据备份遵守现有秘密文件权限，不能进入 Git 或日志。

先在副本中验证旧会话读取、追加、新格式恢复和新旧混合历史，保留原文件。第一期不强制重写旧 session，也不自动提升旧 summary 的可信 marker。发现无法安全解释的记录时停止复用并给出精确恢复路径。

回滚作为两部分处理：

1. 恢复升级前的代码、三个依赖版本、原 patch 和 lockfile，再做 frozen install。优先 revert 升级提交，不 reset 或覆盖用户后来产生的源码工作。
2. 保留升级后会话原件作诊断，回到已验证的旧会话备份或新建独立旧版会话。不得通过删除新 entry、清空 failure ledger 或回退世界事件历史来让旧版本勉强启动。

依赖升级不迁移 source objects、候选 bundle、active revision 或分支 head。即使用户在升级后产生了合法世界事件，也必须保留；如后续实现确实需要世界/编译格式变更，应拆出单独的版本迁移设计。
