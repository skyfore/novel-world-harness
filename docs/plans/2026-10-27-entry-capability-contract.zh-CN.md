# 入口能力契约修复计划

范围：本次已调查的入口状态表达、重复门禁、运行验收与修复范围诊断。复用状态注册表、ActionInvocation、事件提交、requirement/upstream repair 账本；不重写编译器，不重跑已消费的小说修复阶段。

## 缺陷与交付

| 缺陷 | 修复 | 独立验收要求 |
| --- | --- | --- |
| 校验、审计、入口选择与修复规划分别扫描三个字段，忽略最终空值/死亡/撤销，结论受全书角色数影响 | 共享版本化入口状态契约，投影最终状态并检查真实在场；状态有依据与动作可执行分别报告 | null、unset、死亡、梦境、隔离身份拒绝；增加场外角色不改变入口结论 |
| 定性身体状态只能留在文学文本，容易诱导虚构数值或地点 | 在现有注册表中增加有界定性身体状态，要求精确字段证据，沿用未知三值逻辑与 self 可见性 | 未知不自动成为健康/正常；源内局部指代可承载状态，不自动解析真实身份；提交与冷回放一致 |
| 运行探针要求固定地点/计划，再合成计划变化来证明行动 | 从冻结机制/目标发现有界候选，通过现有执行内核提交实际动作，保存绑定入口的事件及效果凭据 | 无动作、前提未知、无实质变化、未来目标均不通过；自主世界驱动仍独立验证 |
| 修复读到末尾才发现不可写/机制缺失，已消费失败仍需清晰归属 | 将状态诊断与可写指针、机制依赖匹配，返回类型化只读缺口及恢复条件，接入现有预检/检查 | 诊断不授予权限、不声称全局不可满足，不更换授权/重置预算/重试消费阶段 |
| 契约变化后旧验收可能被沿用 | 入口验收绑定契约版本，旧结果显式失效，原候选、历史与要求分母保留 | 缺版本或篡改动作凭据不得通过认证 |

## 实施顺序

1. 实现共享入口状态契约与定性字段，接通编译校验、审计、修复规划、运行入口和证据门。
2. 实现真实入口动作探针及凭据校验，保留独立的世界驱动、知识隔离、回放与分支检查。
3. 接通只读修复可行性诊断、工具恢复说明和版本失效；覆盖原失败条件及跨角色/来源的正反例。
4. 运行相关测试、类型检查、语义契约检查和全仓回归；只读复查本地小说，分别报告工程结果与小说未结算项。

代码测试不替代真实小说独立验收。本地已消费的 Pi 修订继续保留；能力变化也不自动授权重放、写入世界或宣告全书完成。

## 兼容性与验证边界

- 目标中的 `candidateAction` 与 `actionPatterns` 可以省略显式 `action`；探针沿用运行内核的规范化规则，依赖验证绑定同一冻结目标，不为通过探针添加能力。
- 开局编译异常保留原错误、会话、草稿与预算。只有正常结束但没有可用开局，才生成语义缺口；未知工程异常不能被改写为原文不足。
- 旧稀疏清单可带警告归档，运行入口不接受单角色存活兜底。入口认证及角色状态展示绑定契约版本，旧结果必须重新评估。
- 修复诊断不授予新写权限。已消费的阶段保持停止，后续语义修订和独立动作／驱动验收仍须遵守原授权与账本。

验证使用 `pnpm check`、`pnpm check:pi-tests`、`pnpm test:semantic-contracts` 与完整 Vitest 回归，并检查原有缺陷在修复前失败、修复后通过。具体执行结果随提交说明记录，不依赖本机临时文件。

代码验证不代替小说验收。局部修复后仍须处理未审消费者、原有要求分母和全书认证，不能由工程测试结果宣告原小说已经解阻。
