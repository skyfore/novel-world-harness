# 消费者复核的场景化执行计划

目标：降低身份修复后消费者复核的重复输入和恢复成本，同时保留原文证据、完整分母、独立验收、稳定任务身份及全部历史消耗。

## 已确认的问题

黑衣狙击手入口的 24 次本地调用分布在四段执行中（7、7、1、9），尚未形成提案。最后一段全部用于读取。冻结角色表 473624 字节中，449250 字节是来源单元 ID 清单。现有流程将保守影响图、全局覆盖清单和模型阅读工作集混在一起；恢复从头编排读取，固定累计调用上限又与已有进展协议不一致。

## 实施步骤

- [x] 增加版本化消费者执行策略，区分局部、跨段和共享依赖工作集；宿主批量准备精确原文与工件，机械覆盖清单转换成可核验的 hash/count 视图，完整清单仍留在原账本。
- [x] 在首次模型调用前检查完整输入及提交空间；模型从初始输入获得完整必读证据，额外证据仍经同源只读工具取得。
- [x] 增加持久草稿预检和有限、稳定的进展里程碑。累计用量不清零，重复读取、预检和改写不刷新窗口；独立验收单独执行。
- [x] 增加显式旧策略迁移，核验原失败会话和所有消耗，追加转换记录；已封存提案优先恢复登记。旧停止、已消费阶段及负面语义结论不能因代码升级自动重跑。
- [x] 以结构化诊断区分原文不足、上下文不足、外部服务拒绝、无进展和登记恢复，提供同作用域的有限恢复指引。
- [x] 增加稳定的逐消息无损编码配置，保留旧编码重建能力；只验证前缀稳定性，不把模拟测试当作真实缓存收益证明。
- [x] 完成真实 Pi 工具链的合成 provider 回归、历史验证、类型检查和代码审查。

交付通过当前分支的 commit 和 push 完成，以本地与远端提交一致作为最终核验。

## 场景与边界

| 场景 | 执行策略 | 验证边界 |
| --- | --- | --- |
| 局部消费者 | 已知依赖批量进入初始证据包，预检草稿后独立提交 | 原要求、当前修订和来源不变 |
| 跨章节／共享角色表 | 共用内容按哈希保存，机械清单由宿主验证，语义内容完整交付 | 全部消费者仍有归属，不依据图裁剪猜测无影响 |
| 证据不足 | 类型化 blocked 判断进入原账本 | 不重试同一负面语义结论 |
| 超大上下文 | 调用前拒绝并给出完整工作集规模和后续拆分依据 | 不静默截断证据，不声称已支持任意大小上下文 |
| 配额／传输失败 | 保留请求、失败和草稿，明确外部等待 | 不清账、不自动无限重试，不把外部拒绝当作语义否定 |
| 已封存结果的登记中断 | 校验同一结果后零生成调用恢复 | 写入结果不明确时先核对，实质依赖变化停止 |

当前全局依赖图保留保守覆盖。字段／时间切面的依赖精化必须先具有完备性证明，不能为了降低预算直接删掉规则、角色或分母。草稿、证据包和进展均不构成世界认证或激活。

## 验收

使用合成大角色表、跨段原文和现有消费者 fixture 测试：证据哈希与覆盖完整；新增工作不再逐页读取机械 ID；初始已交付证据可直接预检；一次草稿进展只能计入一次；重复读取会熔断；独立检查获得决定性原文和提案依赖；登记中断不重放模型；迁移不改任何旧文件；来源、依赖、预算或历史篡改被拒绝。统计模型调用与实际载荷，真实 token／缓存收益另行实测。

2026-10-30 验证结果：`pnpm test` 的 287 个文件通过，2187 项测试通过、4 项跳过；`pnpm run check`、`pnpm run check:pi-tests` 和 `git diff --check` 通过。覆盖真实请求日志里的调用上限停止、重复读取／草稿熔断、零输出配额拒绝、登记中断，以及世界后续变化后历史回执仍可验证。

本地原任务只读迁移预检通过：模型输入 318573 字节，加工具开销及草稿预留为 391594 字节，低于原 512000 字节请求上限。继承累计 358 次调用及 86593651 字节保持不变；32 份原文件核对未变。预检没有调用模型，不代表该消费者已通过语义验收，亦不恢复父编译或认证。
