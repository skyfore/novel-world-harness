## 1. 目标

草案的思路是在现有龙族工作区上按队列补洞。差距分析说明这条路走不通：闭合工作已经原地停了两个月，根因在管线的契约和激励，旧工作区里的台账、回执、名册记录又把每一步修复串行地挡住。

**本次修订的目标**：把编译主干改成召回优先、由宿主分母驱动的形态，丢掉历史包袱，然后从空状态重新编译。

具体是三件事：

1. **内容契约**：世界模型最终必须包含什么，每一项都有不依赖已抽取产物的分母和可执行的度量。在草案九层的基础上增加四层。
2. **精简主干**：新的阶段链、阶段栅栏、缺口循环、轻量名册。旧的名册评审、消费者复验、上游修复、要求台账退役。
3. **干净重启**：旧编译产物导出为只读参考包，换一个空的存储命名空间，清除旧数据，先编译切片再编译全书。

**成功标准**

1. 重启前：新主干在合成夹具上端到端通过；旧产物的参考包已导出并校验；旧命名空间可以一条命令预览并清除。
2. 切片（序幕加第一幕，约 117 KB）：内容契约的全部度量达标或有带理由的未知；至少 3 个可入场的“切面 × 角色”，各自用真实模型连续 20 回合，冷重放一致，零知识越界；得到每 KB 的实测成本。
3. 全书：第 9.2 节的指标达标。

**非目标**

- 不为所有小说设固定的产物密度。目标只针对原文自身陈述的内容。
- 不放松“提案、校验、提交”的边界。宿主候选和领域模块都走同一条校验路径。
- 不引入数据库、向量检索或第二套运行时。
- 不迁移旧数据。旧产物只作参考，不导入新编译。
- 不改运行时内核（`src/world` 的引擎、投影、步进器、准入）。本迭代只动编译侧和它的入口。

## 3. 最终态与内容契约

### 3.1 最终态的来源

最终态来自仓库早期的设计文档（已在 `e5ee6e3` 删除，可用 `git show e5ee6e3^:<路径>` 查看）。逐条对照见差距分析第 3 节，这里只列约束设计的要点：

| 来源 | 要点 |
|---|---|
| `docs/design.md` 第 4、16 节 | 九层中间表示；首要成功标准是玩家干预造成持久的下游差异，分支不被拉回原著 |
| ADR 0006 第 5 节 | 编译要交出五类产物：正典事件、世界规则、角色目标、分歧后仍有效的义务与压力、需要因果选择才发生的正典类比 |
| 语义编译计划第 6、7.2、16 节 | 观察阶段优化召回；记账穷举，可执行建模有选择；十二条完成定义 |
| 编译流程规范第 3、4、7 节 | 宿主按上游清单核对“本阶段应处理什么”；分母不得由产物反推；空规则集不能因为没有校验错误就算齐备 |
| evidence-first 计划第 12 节 | 不强制每个事件有效果、每个角色都成长、全图都有因果 |

由此得到世界模型的目标形状：**观察层接近穷举，节拍层稠密，机制层有选择**。

### 3.2 分母的三种来源

| 来源 | 含义 | 能否被模型“少抽”缩小 |
|---|---|---|
| `source` | 从不可变原文确定性计数：结构单元、直接引语、词表条目的出现、时间表达 | 否 |
| `roster` | 名册：由原文统计得出候选，经一次独立评审确认 | 否；评审缺失时为未知 |
| `internal` | 由已编译产物派生，只检查一致性：场景有地点、事件有效果 | 能，所以不作召回证明 |

每项度量的状态是 `satisfied`、`gap`、`unknown`、`info` 之一。分母为 0 或缺失时为 `unknown`，永不算通过。

### 3.3 逐层契约

目标值属于版本化策略（`completeness-policy-v2`），不是事实。前九层沿用草案，度量已在 M1 实现；后四层是本次新增。

| 层 | 最终态必须包含 | 度量 id | 分母 | 目标 |
|---|---|---|---|---|
| 记账 | 每个基础单元有处置；“背景 / 重复”不掩盖台词和人物；无延后项 | `source.accounted`、`source.hidden-units`、`source.blocking-units` | source | 100%、0、0 |
| 观察 | 每段直接引语有引语标注；每次词表条目的出现有提及 | `observation.speech-annotated`、`observation.names-annotated` | source | 100%、100% |
| 观察 | 直接引语的说话人可追溯到角色 | `observation.speech-attributed` | source | 85% |
| 观察 | 事件提及进入正典或有显式不进入的理由 | `observation.event-mentions-resolved` | internal | 100% |
| 身份 | 一个专名只指一个角色，或有带范围的别名决议 | `identity.name-collisions`、`identity.mentions-resolved` | source / internal | 0、100% |
| 事件 | 每个场景有节拍；事件有效果或显式的无变化；有类型化施事者；台词被节拍承载 | `events.scenes-with-events`、`events.effectful`、`events.typed-agent`、`events.speech-in-beats` | internal / source | 100%、90%、90%、90% |
| 场景 | 叙事被场景覆盖；场景有地点或有理由的未知；说话的人在场 | `scenes.narrative-covered`、`scenes.location-contract`、`scenes.speakers-present` | source / internal | 95%、100%、100% |
| 角色 | 名册角色有模型、倾向、目标，并出现在场景中；名册经独立评审；评审指出的漏掉角色留在分母里 | `characters.speaking-*`、`characters.roster-reviewed`、`characters.roster-modelled` | source / roster | 100% |
| 空间 | 被使用的地点在空间图中；入场人物有位置 | `space.locations-on-graph`、`space.opening-positions` | internal | 100% |
| 知识 | 每次习得有获取路径 | `knowledge.acquisition-paths` | internal | 100% |
| 行动 | 名册角色至少在一个切面可入场，并有改变状态的行动 | `agency.speaking-enterable`、`agency.effectful-goals` | source | 100% |
| **别名与关系** | 别名类提及都落到实体别名；规范名不是代词或普通名词；名册角色两两之间有关系记录或显式“原文未述” | `identity.aliases-attached`、`identity.generic-names`、`relations.roster-pairs` | internal / roster | 100%、0、100% |
| **时间** | 提及范围内有显式时间表达的事件，其故事时间不是序数标签 | `time.anchored-events` | source | 90% |
| **条件与因果** | 关键事件有前置条件、必要原因或经复核的“无条件”；至少有一类分歧后仍有效的产物（义务、压力、过程） | `causality.conditioned-key-events`、`possibility.autonomous-templates` | roster / internal | 100%、至少 1 |
| **设定与规则** | 高频设定术语有落点：概念实体、规则、能力、制度，或带理由的“仅叙述” | `lore.terms-grounded` | source | 100% |

三个定义：

- **有台词的角色**：被归属至少 6 句直接引语的角色。它保证“说得最多的人”不会从分母里消失。
- **名册角色**：有台词的角色，并上事件参与次数靠前的角色，经独立评审增删后的集合。
- **关键事件**：施事者是名册角色、且有非空效果的事件。条件与因果只要求对这个子集建模。

另加两项信息项，不设目标：`cost.per-source-kb`、`cost.per-accepted-artifact`。

### 3.4 仍未纳入度量的契约项

- 角色发展：倾向随经历变化。只对原文确有变化的角色建模，暂以信息项报告。
- 误信与秘密：原文明确写了某人不知道或错信的事。本迭代先建清单，不设目标。
- 反事实测试：破坏某个关键事件的前置条件后它不再发生。在切片验收里按用例检查，不做成全书度量。
- 叙事语义（主题、伏笔）：按原设计排在最后。

## 5. 新主干设计

### 5.1 阶段链

```text
source → census → observation → identity → scenes → world → roster
       → opening → closure → archive → admit
       →（认证轨）evaluation-plan → evaluate → certify → activate → branch
```

| 阶段 | 范围 | 做什么 | 性质 |
|---|---|---|---|
| source | 全书 | 摄入、章节切分、分段、结构单元 | 沿用 |
| census 普查 | 全书 | 建立宿主词表：人名、地名、设定术语、时间表达 | 新增 |
| observation 观察 | 每窗 16 KiB | 宿主预标注，模型确认并补漏；诚实记账 | 重做 |
| identity 身份 | 全书 | 按词表条目做身份决议，宿主派生逐条消解；别名、同名区分 | 从旧语义阶段拆出 |
| scenes 场景 | 每个场景 | 场景、节拍、参与、效果、时间锚 | 从旧语义阶段拆出 |
| world 世界 | 全书，有选择 | 设定与规则、空间、关系、角色模型与目标、条件与因果、知识获取 | 重做旧可执行阶段 |
| roster 名册 | 全书 | 原文统计出候选，一次有界的独立评审 | 取代 `roles` |
| opening | 开场 | 初始世界与读者前情 | 沿用 |
| closure 闭合 | 候选 | 结构校验、完整度报告、切面准入清单 | 重新定义 |
| archive、admit | 候选 | 归档；按切面准入发布和激活 | 沿用（迭代 01） |
| 认证轨 | 候选 | 独立评估计划、真实评测、认证 | 沿用，按新名册适配 |

去掉的阶段：`recover` 里的上游修复恢复（中断回执的恢复并入各阶段开头）、`roles`、`repair`、`requirements`。`converge` 保留为内部步骤。跨片段边界批次暂时保留，切片验收时评估是否还需要。

两条贯穿的规则：

- **阶段栅栏就是度量。** 每个阶段的完成检查调用与完整度报告相同的度量函数，只是限定在本批的原文范围内。一份实现，两处使用，不会出现“批次通过但度量不通过”。
- **前缀编译。** `compile-novel --through-chapter <n>` 只编译批次计划的前缀。迭代 01 的地平线本来就按“话语位置之前没有未处理单元”计算，所以前缀编译出的候选可以直接准入，切片不需要特殊机制。

### 5.2 普查（census）

**为什么需要**：M1 的词法清单依赖已消解的专名提及来建人名词表。从空状态开始时没有这些提及。设定术语和地名则从来没有发现机制。

**做法**

1. 宿主生成候选：说话人位置上的称呼（引语后紧跟“某某说”）；高频、反复出现的多字词；带地点后缀的词（馆、楼、城、室、站）；时间表达式。
2. 模型按章分类候选：人物、地点、机构、物品、设定术语、非实体。一次工具调用提交一批，带每个条目的首次出现作证据。
3. 宿主把确认的条目写入词表库。词表是观察层的东西，不是身份：它只说“这个表面形式是一个值得标注的名字”，不说它指谁。

**栅栏**：出现次数达到策略门槛（10 次）的候选全部有分类；说话人位置上出现 3 次以上的称呼全部有分类。

**词法清单的通用化**（确定性，随本阶段一起做）：引号惯例从弯引号和直角引号扩到直引号和“曰：”。仓库里的《三国演义》用直引号约 8,000 对、“曰：”8,737 处，弯引号只有 304 对。

### 5.3 观察（observation）

1. **窗口**：上限 16 KiB。实现上降低分段上限即可，干净重启不需要兼容旧分段。
2. **宿主预标注**：本窗内的直接引语（带说话人提示）、词表条目的每次出现、时间表达，各生成一条候选，`derivation.worker = "host-lexical-v1"`。
3. **模型的工作**：用批量工具一次性确认、改写或驳回候选；补宿主认不出的东西：代词和称谓的指代（只要求说话人和事件施事者）、间接引语、事件提及、场景与话语边界。
4. **提示词契约**：删掉“不要穷举”，改为“本窗范围内的候选必须逐条处理”。
5. **诚实记账**：单元的“已表示”由宿主从标注覆盖派生。含候选的单元不能用“背景 / 重复”关闭；含直接引语的片段不能声明为无产物。

**新工具**

| 工具 | 作用 |
|---|---|
| `review_observation_candidates` | 批量接受、改写（如改说话人）、带理由驳回宿主候选 |
| `propose_entity_mentions`、`propose_quotations` | 批量新增标注，替代逐条调用 |

**栅栏**：本窗 `observation.speech-annotated` 和 `observation.names-annotated` 为 100%（驳回计入）；`source.hidden-units` 为 0；每个叙事单元属于某个场景或话语片段。

### 5.4 身份（identity）

旧流程对每条提及单独做消解。龙族有 5,170 次人名出现，逐条决议既贵又没有信息量。

**做法**

1. 模型按词表条目做决议：“这个表面形式在全书（或某个范围内）指实体 X，别名类型是 Y，例外见下”。一个条目一次决议。
2. 宿主据此为每条专名提及派生消解记录，`derivation.worker = "host-lexicon-v1"`，依据指向那次决议。
3. 需要逐条决议的只有三类：同名冲突（如两个路鸣泽）、代词与称谓、模型标为歧义的条目。
4. 设定术语和地名在这里成为概念实体和地点实体。
5. 规范名不允许是代词或普通名词。原文未给名字的人物用带“派生”标记的标签。

**栅栏**：`identity.mentions-resolved`、`identity.aliases-attached` 为 100%；`identity.name-collisions`、`identity.generic-names` 为 0。

身份决议仍然是模型的提案，宿主只做展开。“词面相同只提出候选，不证明身份”这条原则不变。

### 5.5 场景（scenes）

以观察阶段确立的场景边界为单位，一个场景一批。

每个场景交出：

- 场景记录：地点或带理由的“未知”，在场者，出入条件（原文有则写）。
- 节拍：每个节拍有类型化的施事者、在场方式、效果（状态、知识、关系），或显式的“原文支持无变化”及理由。
- 时间：本场景范围内有显式时间表达时，给出相对或精确的故事时间和时间推进。
- 事件证据用提及范围，不再用整段的宽跨度。

**栅栏**：本场景内每段直接引语落在某个节拍的范围内；被标为主要的事件提及全部进入正典或有理由地不进入；说话人都在场；场景有地点契约。

不要求每个节拍非空。“无变化”必须是显式审阅的结论，不能由空增量推出。

### 5.6 世界（world）

全书范围，有选择。宿主从分母生成工作项，模型逐项处理，每项要么交出产物，要么给出带理由的“原文未述”。

| 工作项来源 | 产物 | 对应度量 |
|---|---|---|
| 词表里的每个设定术语 | 规则、能力（行动机制）、制度（规范或过程）、概念实体，或“仅叙述” | `lore.terms-grounded` |
| 被场景或位置使用的每个地点 | 包含、相邻、路线关系，或“未知” | `space.locations-on-graph` |
| 共同出场 2 次以上的名册角色对 | 有方向的关系记录，或“原文未述” | `relations.roster-pairs` |
| 每个名册角色 | 角色模型（倾向带情境和证据）、目标（带改变状态的候选行动） | `characters.*`、`agency.effectful-goals` |
| 每个关键事件 | 前置条件、类型化的因果依赖、阻断条件，或经复核的“无条件” | `causality.conditioned-key-events` |
| 原文里的期限、职责、追踪、制度反应 | 义务、压力、过程的可能性模板 | `possibility.autonomous-templates` |
| 每次习得 | 获取路径 | `knowledge.acquisition-paths` |

**行动的三个来源**（决策 D2）

1. **领域模块**：说话、移动、观察、交付、取用。由宿主提供，`induction.kind = "domain-module"`，前提与效果由宿主规则校验。任何小说都有，不需要原文证据。
2. **原文明确陈述**：新增 `induction.kind = "source-statement"`。原文明确写出某种能力或做法时，一次即成立。源文专有的能力（如某个言灵）走这条。
3. **源文模式**：沿用，至少两个支持事件。

领域模块不能把单次事件推广为可重复能力，也不能绕过知识和在场的校验。

### 5.7 名册（roster）

1. 宿主从原文统计候选：有台词的角色，并上事件参与次数靠前的角色、视点角色。
2. 一次有界的独立评审：新会话，只拿到原文统计和抽样段落，不拿已编译的角色模型。它只回答两个问题：候选里谁是主要角色；有没有漏掉的主要角色。
3. 漏掉的角色进入名册并保留在分母里，即使还没有实体。

名册没评审时 `characters.roster-reviewed` 为未知。这只阻塞全书认证，不阻塞其后的阶段和切面准入（决策 D7）。

### 5.8 闭合与缺口循环

**闭合**由三部分组成，取代旧的十一个维度：

1. 结构与证据校验：沿用现有审计和校验器里与退役族无关的部分（引用闭合、证据绑定、时间与因果图合法）。
2. 完整度报告：范围内没有 `gap`，`unknown` 都带理由。
3. 切面准入清单：沿用迭代 01。

**缺口循环**（`compile-novel gaps`）实现 `design.md` 第 6 节设想的缺口驱动流程：

1. 对候选算完整度报告，得到修复队列。
2. 宿主排序：先挡住地平线的，再按层的依赖顺序（观察、身份、场景、世界）。
3. 为队首开一个有界范围：一段原文加目标对象。范围内可以使用任何阶段的提案工具（决策 D3）。
4. 模型提案，宿主校验提交。完成条件是这个范围的度量达标，或该项有了带理由的处置。
5. 同一项失败两次进入“待宿主复核”清单。循环继续处理其他项，不整体停下。

没有逐产物的台账，没有前缀锁，互不相关的项可以并行。

每个可能为 `gap` 的度量都有修复队列（2026-11-20 补齐）。比例型度量（说话人归属、类型化施事者、节拍内台词、时间锚定）的单项可以用带理由的例外关闭，例外不计入分子，由目标余量吸收；被复核为“仅叙述”的片段计入叙事覆盖。

### 5.9 成本可见

每次阶段运行记录输入、输出、缓存 token 和名义成本，并按“每 KB 原文”和“每条被接受的产物”折算，进入 `compile-novel status` 和完整度报告。观察确认这类低歧义工作可以配置便宜的模型档位，身份、场景、世界用强模型。

### 5.10 沿用 M1 的部分

- **宿主词法清单**（`src/compiler/lexical-inventory.ts`）：直接引语与引号词语的区分、三条保守的说话人规则。词表来源从“已消解的专名提及”改为普查词表；通用化见 5.2。
- **台词参照回补**（`src/world/voice-references.ts`）：不变。新编译里引语标注接近全量，词法提示的占比会自然下降。
- **完整度报告**（`src/compiler/world-completeness.ts`）：增加 3.3 节的四层和成本信息项；增加按原文范围度量的入口，供阶段栅栏使用。

## 6. 干净重启

### 6.1 三步

**第一步：导出参考包**（旧代码还能读旧数据时做）

`nwh compile-novel reference export --source <id>` 把旧候选压成一份只读的参考包，写到 `$NWH_HOME/archives/<项目>/legacy-reference/<源>-<日期>/`：

| 文件 | 内容 |
|---|---|
| `manifest.json` | 源哈希、管线与提示词版本、导出时间、各文件的条数与哈希 |
| `entities.json` | 实体的类型、规范名、别名、带别名类型的消解表面形式、提及数 |
| `events.json` | 事件标题、读者摘要、提及范围（字节）、参与者、效果摘要 |
| `scenes.json`、`relations.json` | 场景范围、地点、在场者；事件关系 |
| `characters.json` | 角色模型、目标、规范、行动机制 |
| `quotations.json` | 带说话人的引语标注及字节锚点 |
| `reports.json` | 完整度报告、时间线、闭合快照、用量汇总 |

预计几 MB。导出后用清单里的哈希校验一遍。

**第二步：换命名空间**（决策 D5）

| 版本 | 现在 | 之后 |
|---|---|---|
| 世界存储 `WORLD_STORAGE_VERSION` | v3 | v4 |
| 预编译缓存目录 | `prepared-novels/v3` | `prepared-novels/v4` |
| 编译管线版本 | 50 | 60 |
| 提示词版本 | 51 | 60 |

升版之后新代码只读写新命名空间，旧数据即使还在磁盘上也不会被读到。

**第三步：清除旧数据**

`nwh maintenance purge-legacy` 先预览、后确认。它是通用能力，不是针对龙族的脚本。

| 清除 | 保留 |
|---|---|
| 各工作区下旧版本的 `world/v1` 到 `v3` | `sources/v1` 的不可变原文 |
| `prepared-novels/v1` 到 `v3` | `archives/`（含参考包） |
| 工作区下的 `compile-loops` | 新命名空间 `world/v4`、`prepared-novels/v4` |
| 切换日期之前的追踪 | 切换日期之后的追踪 |
| 遗留的临时工作区（本机有 5 个，各不到 200 KB） | 项目登记和 Pi 登录信息 |

预览列出每一项的路径和大小。执行需要用户确认。

### 6.2 时间顺序

```text
导出参考包并校验（M2）
  → 新主干落地，旧族删除，版本升级（M3、M4）
  → 切片编译并验收（M5）
  → 清除旧数据
  → 全书编译（M6）
```

旧数据留到切片验收通过再清。升版之后它已经读不到，留着只是一份原始备份，没有成本；清除不可恢复，放在新主干被证明能用之后。

### 6.3 参考包怎么用

| 用途 | 做法 | 性质 |
|---|---|---|
| 回归对照 | `compile-novel compare --reference <包>`：在新编译覆盖的范围内，列出旧编译有而新编译没有的实体（按名字）和事件（按提及范围重叠） | 复核清单，不是门禁，不是分母 |
| 普查交叉核对 | 旧实体名里没被普查词表收录的，列出来供检查 | 只提示，不导入 |
| gold 切片草稿 | 切片范围内的旧标注和事件作为标注起点，每一条都要对照原文确认，并记录草稿来源 | 省标注时间 |
| 规则校准 | 160 条旧引语标注（其中 144 条的说话人解析到角色），用来抽查词法说话人规则 | 确定性测试数据 |

不允许：把旧产物放进新编译的提示词或目录；导入旧提案；把旧 ID 当作权威。旧编译有“他”“男人”这类错误实体和 8,765 个被掩盖的单元，导入会把这些问题带进新世界。

### 7.2 做法

1. 以 4.2 节的导入图为清单，先改 36 个接入点，让它们不再引用退役族。`compilation-closure.ts`、`certification.ts`、`prepared-cache.ts` 是改动最大的三处。
2. 再删退役族和对应测试。删除后 `pnpm check` 和 `pnpm test` 必须通过。
3. 每删一族单独提交，提交说明里写被哪个新机制取代。旧代码留在 git 历史里。

### 7.3 需要你确认的一项

**外层工程循环**（`src/runtime/compile-loop/*`、`compile-novel-loop`，11 个文件、1,176 行）在编译子进程失败后启动一个工程会话去诊断并修改 harness 源码。它是产品功能，不是修复机制的内部件，所以没有放进默认的删除范围。我的建议是退役：新主干里领域缺口由缺口循环处理，工程故障由开发者修；自动改源码的循环是 183 次外层尝试那个阶段的产物。不确认的话，本迭代只把它对接到新的阶段名。

## 9. 验收

### 9.1 切片

范围：序幕加第一幕，117 KB，约占全书 15%，含约 600 处引号（直接引语和引号词语合计）。

| 项 | 标准 |
|---|---|
| 内容契约 | 3.3 节的度量在切片范围内全部达标，或为带理由的未知 |
| 可入场 | 至少 3 个“切面 × 角色”通过全部确定性探针 |
| 试玩 | 每个入口用真实模型连续 20 回合；冷重放一致；零知识越界；死回合率低于 0.5 |
| 反事实 | 至少一条用例：破坏某个关键事件的前置条件后，该事件不再发生，后续正典不被强制拉回 |
| 精度 | gold 切片（2 到 3 个场景，约 20 KB）上，提及、引语说话人、事件各层的精确率和召回率都有实测值，记入进度文档。本轮不设门槛，只建立基线 |
| 成本 | 得到每 KB 原文的 token 与名义成本；据此估算全书预算，由你确认后才进入 M6 |
| 回归对照 | 参考包里落在切片范围内的旧实体和事件，新编译要么重现，要么在复核清单里有说明 |

## 10. 不变量

1. 原文是证据边界。模型输出只是提案，经宿主校验后提交。
2. `source` 分母只从原文计数，不能被抽取结果缩小；`unknown` 永不算通过。
3. 宿主候选、按词表展开的消解、领域模块，都留有派生记录，都可以被模型或宿主驳回。
4. “无变化”“原文未述”“未知”是合法结论，但必须是显式审阅的结果。
5. 旧产物不进入新编译。
6. 阶段栅栏与完整度报告使用同一套度量实现。
7. 运行时内核、分支历史语义、知识隔离不因本迭代改变。

## 11. 风险

| 风险 | 对策 |
|---|---|
| 新主干改动面大，M3 周期长 | 阶段逐个落地，每个阶段先在合成夹具上通过；M2 不依赖 M3，可以先交付 |
| 删除旧代码后发现还需要其中的能力 | 只删新主干不再调用的；有用的纯函数搬走；旧代码在 git 历史里 |
| 召回提高后成本失控 | 宿主预标注和批量工具压低观察成本；切片实测每 KB 成本，全书预算经确认后才启动 |
| 指标变成伪造事实的压力 | 目标只针对原文自身陈述的内容；保留显式的无变化与未知；gold 切片量精度 |
| 按词表做身份决议放大错误（一个错的决议影响几百条提及） | 同名冲突和歧义条目强制逐条决议；回归对照和 gold 切片会暴露系统性错绑 |
| 普查漏掉低频但重要的名字 | 观察阶段模型可以新增提及；新表面形式回流进词表，触发受影响窗口的补标 |
| 只在龙族上调出的策略不通用 | M2 就在《三国演义》片段上跑确定性层；M7 复查策略值 |
| 领域模块让世界变得“什么都能做” | 模块只覆盖五种基础行动，前提和效果由宿主规则校验；专有能力仍需原文证据 |
| 测试重写量大（旧阶段的提示词夹具失效） | 计入 M3、M4 的工作量；删除的 85 个测试文件不需要重写，只有主干的批次测试需要 |
