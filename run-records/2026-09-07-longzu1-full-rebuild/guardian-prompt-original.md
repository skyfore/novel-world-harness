四、问题分级与停止协议——最高执行优先级

遇到错误或异常时，先判断是否构成本轮目标的 blocker，再决定后续动作。本协议覆盖其他持续执行、恢复或重试要求。

判断依据：
能否在保持数据正确性、证据链完整性和恢复安全性的前提下，继续完成整本候选编译。

以下情况属于 block：
- 必要凭据、权限、依赖或 provider 不可用，当前无法继续；
- 原文完整性异常、状态损坏、并发写冲突或版本不兼容；
- 必需工件或依赖缺失，校验失败阻止合法提交；
- 继续执行可能污染世界真值、破坏检查点或丢失恢复依据；
- 必须修改代码、编译契约或放宽校验才能继续；
- 必需阶段已失败，且没有项目明确支持的安全恢复路径。
无法确定是否影响正确性时，保守按 block 处理。

确认 block 后：
1. 立即停止调度新任务，不继续自动重试、修复或跳过，不继续其他编译分支。
2. 如果有在途编译，使用项目支持的取消方式安全停止。不要强杀正在提交的写进程；若无法确认安全停止方式，明确报告进程状态，不冒险操作。
3. 仅进行必要的只读上下文收集；允许写入诊断报告，但不修改编译状态。
4. 不重新执行失败的写操作来复现问题。
5. 保留日志、journal、检查点、提案及现场，不清理、不重置。
6. 提交阻塞报告并结束本轮执行，等待我下一步指令。
7. 可以提出修复建议，但不要自行执行修复。

非 block 的处理：
- 只有当前流程明确支持跳过，且不影响必要依赖和本轮完成条件时，才允许跳过并继续。
- 可选展示失败、辅助统计缺失等可以属于非 block。
- 必要批次、证据校验、身份解析或提交失败，不能为赶进度而归入非 block。
- 跳过不等于成功：保留真实失败状态，不手改完成标记，不填空结果冒充通过。
- 记录触发场景、跳过依据和影响范围；后来发现影响扩大时，立即升级为 block。

模型工具恢复边界：
- 遵循 docs/agent-tool-recovery.md。
- 若 ID/ref 错误属于协议明确支持的非阻塞可恢复情况，使用同作用域 discovery 工具，复制真实返回字段，最多一次有实际修正的重试；禁止猜 ID 或原样循环。
- 若该错误已构成 block，立即停止，不执行上述重试。
- 不在项目已有有限恢复机制之外叠加无限重试或守护重启循环。
- 对暂时无输出、传输抖动和限流，依据工具真实状态与既有恢复协议判断，不能仅凭等待时间认定失败，也不能无限等待。
