# 开局编译阻塞修复报告

## 已实施的修复及其依据

1. **输入契约一致性**：工具 JSON Schema 使用 Zod input 模式，默认数组可以省略；开局 Schema 公开必需的五种 reader fact，以及 actor-stance 的 holderEntityId/stance、social-stakes 的 holderEntityId 条件。完整 Zod 校验继续保留。这样模型看到的契约与实际输入校验一致，避免输出 Schema 将默认值误报为必填。
2. **一次报告独立错误**：初始世界提交前同时检查 payload 与 evidence_selectors。真实第一次失败输入现在一次列出缺少 holderEntityId、stance、causal-premise，以及 relation=explicit 非法四类错误，避免修复第一层后才发现下一层。
3. **只读预检**：新增 preview_initial_world，限开局/协调批次，检查输入、精确原文选择器和字段级证据。成功也不创建提案、不提交世界、不清除失败记录。图闭包、提交、可玩性明确不在其认证范围；正式提交与 finish 重新校验。每个批次会话最多原始预检及一次有变化的修正，原样重复或超额要求主机审查；持久化 proposal/finish 阻塞仍优先执行。
4. **正确恢复身份**：恢复 SOP 要求未成功暂存的失败调用沿用原 tool/proposal_id；一次修正需要处理全部已报告错误。代词标注 surface 必须与 selector.exact 完全相同，不得通过换 ID 逃避原失败记录。
5. **保护失败现场**：开局发生主机审查错误、仍有未解决义务或保存的 finish 时，prepare-all 保留草稿并抛出原始错误，不再拒绝这些草稿后进入 fallback，避免覆盖真正根因。
6. **可观察性**：独立开局/协调编译建立自己的追踪，包括创建模型会话前就被阻止的失败；各恢复尝试有独立 attempt。只读状态扫描实际持久化的补充批次，显示开局义务，与普通批次完成度分别报告。

提示版本由 31 升到 32；流水线版本仍为 34，因此不要求重跑已验证的普通批次。
